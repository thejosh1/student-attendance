1. EXECUTIVE SUMMARY
----------------------------------------------------------------------------------------
The WiFi Proximity OTP Check-in system is a fraud-proof, proximity-bounded attendance
mechanism designed for Nigerian university lecture halls (specifically modeled for FUTO).
It solves proxy attendance and remote check-in fraud by marrying physical RF signal
attenuation (<50 feet indoor radius) with time-based cryptographic rolling OTP tokens
synchronized in real-time across the hardware terminal (ESP32) and the cloud dashboard.

Students physically present in the lecture hall observe a rolling 6-digit code via
either the terminal's 16x2 LCD display or their smartphone's WiFi network list
(Zero-Connect SSID Beacon), and submit their matriculation number and OTP on the web app.

2. ARCHITECTURE: WHAT WAS BUILT
----------------------------------------------------------------------------------------

A. EMBEDDED HARDWARE SUBSYSTEM (ESP32 FIRMWARE)
File: firmware/futo_attendance_esp32.ino
- Dual Mode WiFi (WIFI_AP_STA):
  The ESP32 microcontroller operates concurrently as an HTTPS station client connected
  to the university/cloud network, and as an open SoftAP broadcasting within the room.
- Clamped Radio RF Power (< 50 Feet / ~15-20m Radius):
  WiFi transmit power is capped to WIFI_POWER_8_5dBm (~7 mW) instead of the default 19.5dBm.
  This physically confines the beacon signal within the lecture hall walls, preventing
  students in dorms, cafeterias, or outside the hall from detecting or receiving the code.
- Zero-Connect SSID Beacon ("WORC-OTP-[CODE]"):
  The SoftAP dynamically broadcasts an open network SSID containing the active 6-digit OTP
  (e.g., "WORC-OTP-739786"). Students do not need to disconnect from mobile data or join
  the WiFi network; they simply open their phone's WiFi menu, read the code, and submit it.
- Local Captive Proximity Portal (192.168.4.1):
  If students connect directly to the terminal's AP, an embedded lightweight HTTP server
  serves a local landing page showing the active course, live rolling OTP, and a direct link.
- 16x2 I2C LCD Live Synchronization:
  The hardware screen displays the course name and rolling countdown:
  Line 1: "TCE 511 [LIVE]"
  Line 2: "OTP: 739786 (16s)"
- Cloud Polling & Session Sync:
  Every 3.5 seconds, the terminal calls "/api/biometric/session?deviceId=DEV-FUTO-01",
  receiving authoritative session status, lecturer controls, and OTP synchronizations.

B. BACKEND & CRYPTOGRAPHIC ENGINE (NestJS & Next.js API)
Files:
- lib/store.ts
- server/nestjs-architecture/services/biometric.service.ts
- server/nestjs-architecture/controllers/biometric.controller.ts
- app/api/attendance/otp/route.ts
- app/api/biometric/session/route.ts

1. Rolling Window OTP Generation & Verification:
   - Secret HMAC-SHA256 seed ("futo_worc_otp_secret_key_2026").
   - 60-second time-window calculation: Math.floor(Date.now() / 60000).
   - Generates a cryptographically strong 6-digit decimal code (100000 to 999999).
   - Grace-Period Window Verification: Validates both current window (offset 0) and
     previous window (offset -1). This gives students a 60-second grace window so
     submissions during a minute transition are never unfairly rejected.
   - Rejects future windows, expired windows (>= 2 minutes old), and foreign sessions.

2. Comprehensive Business Rules & Anti-Fraud Logic (processOtpCheckin):
   - Input format validation: strict 6-digit numeric regex (/^\d{6}$/).
   - Student identity verification: verifies Matric/Reg No against enrolled directory.
   - Active Lecture Session check: prevents check-ins when class is idle or has concluded.
   - Lecturer Device Lockout (HTTP 403): immediately blocks attendance check-ins if
     the lecturer disables the assigned terminal on their control panel.
   - Automatic Class Expiration: sessions automatically conclude once the scheduled
     endTime is reached.
   - Duplicate Check-in Prevention: prevents students from submitting attendance multiple
     times for the same lecture (returns duplicate status, original check-in time intact).
   - Punctuality Evaluation: compares timestamp against session lateCutoff to mark
     student "present" or "late".
   - Audit Trail & Storage: records attendance with method badge "wifi_otp", timestamp,
     device ID, and persists to MongoDB / in-memory store.
